## 4. Temuan Gap & Bug Selama Verifikasi Serta Perbaikannya

Selama siklus pengujian, ditemukan beberapa penyesuaian teknis dalam cakupan yang langsung diperbaiki dan diuji ulang hingga lulus:

1. **Sinkronisasi Copy Pratinjau Cuti Non-Saldo (B15)**
   - *Akar Masalah*: Pemeriksaan automasi browser menguji teks `'tidak memotong saldo cuti'`, sementara model backend menampilkan redaksi `'tidak memengaruhi saldo cuti'`.
   - *Perbaikan*: Automasi `tools/mobile-qa/approval_ui_browser_qa.mjs` diperbarui untuk memverifikasi `'tidak memengaruhi saldo cuti'` dan ketiadaan klaim `'cadangan cuti'`. Uji ulang B15: **Lulus**.
2. **Kondisi Baris pada Uji 409 Conflict (B16)**
   - *Akar Masalah*: Pengujian konflik versi sebelumnya menargetkan baris izin yang sudah difinalisasi, menyebabkan otorisasi server menolak dengan `403` sebelum memeriksa versi.
   - *Perbaikan*: Target pengujian diarahkan ke baris pending reviewable `non_balance_permission_id`. Server mengembalikan `409 Conflict` dengan pesan peringatan yang benar. Uji ulang B16: **Lulus**.
3. **Cookie Session Lingkungan Browser (B17)**
   - *Akar Masalah*: Cookie sesi pengguna sebelumnya masih aktif di Puppeteer sehingga saat browser diarahkan ke `/login`, middleware `guest` Laravel me-redirect kembali ke `/home`.
   - *Perbaikan*: Ditambahkan pembersihan cookie via CDP `Network.clearBrowserCookies` sebelum membuka formulir login akun nonaktif. Uji ulang B17: **Lulus**.
4. **Culling Komponen pada Viewport Uji Flutter (F03 & F05)**
   - *Akar Masalah*: Viewport default `WidgetTester` (800×600) menyebabkan tombol di bagian bawah `ListView` detail belum ter-render pada tree widget.
   - *Perbaikan*: Menambahkan konfigurasi `tester.view.physicalSize = const Size(430, 1200)` pada awal pengujian widget. Uji ulang F03 & F05: **Lulus**.
5. **Selector Tombol Dialog Pembatalan (F05)**
   - *Akar Masalah*: Label tombol aksi dialog pembatalan cuti disetujui adalah `'Kirim permohonan'`, bukan `'Ajukan pembatalan ke HR'`.
   - *Perbaikan*: Penargetan finder disesuaikan ke `find.text('Kirim permohonan')`. Uji ulang F05: **Lulus**.
6. **Ketepatan String Error Konflik Datasource (F08)**
   - *Akar Masalah*: Pemeriksaan string error 409 memeriksa `'Pengajuan berubah'`, sedangkan pemetaan datasource aktual menghasilkan `'Pengajuan sudah berubah atau sudah final...'`.
   - *Perbaikan*: Assertion disesuaikan dengan string resmi pada `submission_remote_datasource.dart`. Uji ulang F08: **Lulus**.
7. **Isolasi Token Pengguna Antar Sesi (F09)**
   - *Akar Masalah*: Mock `loginUser()` memakai token konstan sehingga saat pengguna berganti ID, pengecekan token tidak mendeteksi perubahan sesi.
   - *Perbaikan*: `loginUser(userId)` diperbarui menyimpan token berbasis ID (`'qa-mock-token-$userId'`). Uji ulang F09: **Lulus**.
8. **Interferensi Antar-Zone FakeAsync pada Static Futures Datasource (F04–F09)**
   - *Akar Masalah*: Variabel antrean serial statis `AuthLocalDatasource._pending` mempertahankan future dari zone `FakeAsync` pengujian sebelumnya yang sudah tertutup, menyebabkan pemanggilan serial di pengujian berikutnya membeku.
   - *Perbaikan*: Menambahkan utilitas `@visibleForTesting static void resetForTesting()` pada `AuthLocalDatasource` yang dipanggil pada `setUp()`, serta menyederhanakan `loginUser()` pada harness pengujian agar langsung memutasi mock `SharedPreferences`. Uji ulang F01–F10: **Lulus 100%**.
9. **Bukti Mutasi Nyata pada Pencegahan Double-Click Web (B10)**
   - *Akar Masalah*: Harness B10 sebelumnya hanya memanggil assertion statis tanpa mengintersepsi jumlah request HTTP riil atau mengecek kondisi record di database pasca klik ganda cepat.
   - *Perbaikan*: Ditambahkan flag pengunci `isSubmitting` pada form konfirmasi `submission-approval.blade.php`, pelacakan request HTTP POST ke endpoint `/submission-decisions/permission/{id}` dengan hasil tepat 1 kali pemanggilan, serta kueri database SQLite langsung yang membuktikan `submission_approval_events` bertambah persis +1, `approval_version` bertambah persis +1, dan entri `leave_balance_ledgers` tidak termutasi ganda/prematur. Uji ulang B10: **Lulus**.
10. **Pembuktian Refresh Otomatis Daftar Mobile Pasca Navigasi Balik (F07)**
    - *Akar Masalah*: Pengujian F07 sebelumnya hanya menekan tombol Back pada halaman detail terisolasi tanpa memvalidasi apakah halaman daftar (`SubmissionListPage`) otomatis memanggil refresh dan memperbarui status item.
    - *Perbaikan*: Harness F07 diperluas menguji interaksi dari `SubmissionListPage` membuka `SubmissionDetailPage`, mengajukan pembatalan cuti disetujui, lalu menekan tombol Back. Terverifikasi bahwa `SubmissionDetailPage` ter-pop bersih, callback `await _list.refresh()` terpanggil (`listLoads == 2`), dan status pada antrean daftar otomatis berubah menjadi `'Menunggu pembatalan'` menggantikan status lama `'Disetujui'`. Uji ulang F07: **Lulus**.

## 5. Batasan Lingkungan Pengujian

Sesuai instruksi batasan proyek:
1. **Headless Browser QA vs Manual E2E Multi-User**: Verifikasi browser dashboard dijalankan secara otomatis melalui Chromium headless (Puppeteer CDP) pada server QA lokal loopback `127.0.0.1:8018` dengan SQLite memory fixture. Skenario mencakup interaksi DOM nyata, penanganan modal dialog, klik tombol, keyboard Escape, pencegahan mutasi ganda, dan query verifikasi database. Pengujian ini belum mencakup pengujian manual multi-user secara bersamaan di lingkungan staging/production dengan jaringan publik.
2. **Flutter Widget/Unit Test vs Integrasi Perangkat / Emulator Android Nyata**: Seluruh skenario mobile F01–F10 diverifikasi melalui unit dan widget testing terisolasi lengkap dengan simulasi rendering, MediaQuery, tema gelap/terang, event datasource, navigasi Navigator/PopScope, dan auto-refresh daftar. Pengujian integrasi live (*integration_test*) pada perangkat fisik atau emulator Android yang terhubung langsung ke backend HTTP nyata belum dijalankan pada sesi ini.
3. **Batasan Klaim Kesiapan**: Hasil pengujian membuktikan bahwa perapian alur dan antarmuka approval HR/Atasan telah bekerja sesuai spesifikasi pada level unit, widget, dan browser automated test. Namun, klaim 100% kesiapan produksi penuh tetap dibatasi hingga pengujian integrasi live Android dengan backend dan pengujian beban multi-user diselesaikan pada tahap berikutnya.
4. **Database Utama**: Database MySQL utama pengguna tidak dimutasi sama sekali; seluruh mutasi pengujian berlangsung pada direktori disposable SQLite QA terisolasi yang telah dibersihkan kembali setelah pengujian selesai.
5. **Kebijakan Git**: Tidak dilakukan `git commit`, `git push`, maupun deployment server.
